# Desktop development-build tests (ARCHITECTURE.md 6.7)

`npm run desktop:test -- dev` runs these with Playwright's Electron support against the app started
from source: `desktop/src` compiled into `desktop/dist`, and the production build of `app/` served
under `app://`. In CI they run on `macos-15` (job `desktop-dev`, after `npm run build`). They run on
Windows and Linux too; what only macOS can show is skipped there with its reason.

No window appears or takes the focus: the harness sets `EASY68K_DESKTOP_TEST_WINDOWS=hidden`
(`inactive` for the full-screen test: shown off-screen without the focus), which only these tests
set. Every Electron process is closed by its process id.

## What only the macOS run shows

| Test                                                                                                     | Why not on Windows or Linux                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `menu.spec.ts` "on macOS the application menu bar shows the menu of the window in front, with its roles" | The application menu bar, the `appMenu`, `editMenu`, `window` and `help` roles and the items `services`, `hide`, `hideOthers`, `unhide`, `zoom` exist only in macOS menus. Elsewhere each window gets its own (hidden) menu and those roles are left out; the other menu tests check the menu description and its Electron translation on every OS. |
| `windows.spec.ts` "window-level full screen for the Output panel"                                        | On macOS full screen moves the window into its own Space. On a Windows machine that someone is using it would cover their screen.                                                                                                                                                                                                                   |
| `menu.spec.ts` "Cmd+C and Cmd+V ... in the Memory panel's Address field"                                 | Runs everywhere, with Cmd on macOS and Ctrl elsewhere. A key chord sent by Playwright reaches the page directly, not through the menu's key equivalents, so this test cannot fail when the role items are broken; that the OS-level Cmd+V goes through the role item is on the manual list of 6.8.                                                  |
| `menu.spec.ts` "the Edit menu's role items Select All, Paste and Copy work ..."                          | Skipped on macOS. It performs the role items themselves, as Electron does for a click on Windows and Linux (the role's method on the window's web contents). macOS performs role items through the first responder, which a hidden test window does not have; there it stays on the manual list of 6.8.                                             |
| `output.spec.ts` "Alt+Enter in the Output panel ..."                                                     | As the full-screen test below: it would cover the screen of whoever uses a Windows machine.                                                                                                                                                                                                                                                         |
| `unit.spec.ts` "only the role chords of macOS reach the menu"                                            | Runs everywhere, but the role chords exist only in the macOS key map; on Windows and Linux no key reaches the menu.                                                                                                                                                                                                                                 |
| `unit.spec.ts` "macOS with no window left ..."                                                           | Runs everywhere with a stand-in for Electron's `Menu`; that the real macOS bar shows that menu after the last window closes, and that Cmd+N there opens a window, only a macOS run (6.8 manual list) shows, since the tests quit the app with its last window.                                                                                      |
| `windows.spec.ts` "an open-file event ..."                                                               | Runs everywhere by sending the `open-file` event that macOS sends; a real Finder association or a drop on the Dock icon is checked by DV3 on the packaged app (6.7 check 3).                                                                                                                                                                        |

## Environment

- `EASY68K_APP_DIST`: the production build to serve. Default: `app/dist` in CI, otherwise a build of
  its own in `build/desktop-dev/dist` (never `app/dist`, which other work on the same machine may use).
- `EASY68K_DESKTOP_SKIP_BUILD=1`: reuse `build/desktop-dev/dist` and `desktop/dist` as they are.
- `EASY68K_REQUIRE_ENGINES=1` (CI): a missing `engine/dist` fails the engine test instead of skipping it.
