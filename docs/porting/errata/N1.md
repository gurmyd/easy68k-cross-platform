# Errata of N1 (dock layout)

Where `docs/ARCHITECTURE-PLUS.md` is silent, ambiguous, or cannot be met as written with
flexlayout-react 0.11.1, what the code does and why. None of these entries changes what a 68000
program can observe, a file the application writes, panel visibility, or an original menu, command
or key (P1.1).

## 1. `tabSetEnableClose: true`, not `false` (P2.2)

P2.2 lists `tabSetEnableClose: false` and `tabSetEnableDeleteWhenEmpty: true`. FlexLayout 0.11.1
deletes an empty group only when the group "can be closed" (`RowNode.tidy`:
`child.isEnableDeleteWhenEmpty() && child.isEnableClose()`), so with `false` a group whose last panel
is moved away or closed stays on screen as an empty box, against P3.1.8 ("A group whose last panel is
closed disappears"). The dock sets `tabSetEnableClose: true`. What P2.2 wanted from `false` still
holds: no group shows a close button (`tabSetEnableCloseButton: false`), and `onAction` refuses
`DELETE_TABSET` of a group that holds a panel (`ui/dock/rules.ts`). `model.test.ts` has the row.

## 2. Model options P2.2 does not list (`ui/dock/model.ts` `globalAttributes`)

Added, each to keep today's look or to keep a feature P2.2 switches off from coming back through
another option: `tabEnableScrollbars: false` (each panel scrolls inside itself, as today's regions;
FlexLayout would put an extra scrolling box around it), `tabCloseType: 2` (Always: a tab's x closes
it also when the tab is not selected, as the kit's tool tabs do today), `tabEnablePin: false`,
`tabEnablePopoutIcon: false`, `tabEnableFloatIcon: false`, `tabSetEnableSingleTabStretch: false`.

## 3. `tabDragSpeed={0}` has no effect in 0.11.1 (P2.2, P3.1.8)

`LayoutController.getTabDragSpeed()` is `this._props.tabDragSpeed ? ... : .3`, so 0 means the default
of 0.3 s. Under `prefers-reduced-motion: reduce` the dock passes `0.0001` and `dock.css` sets
`transition: none !important` on FlexLayout's drop outlines (an `!important` rule wins over the inline
`transition` FlexLayout writes). `check-dock.mjs` (boxes) checks the computed transition is `0s`.

## 4. The tab strip is 29 px tall: 28 px of tabs and a 1 px border (P3.1.4)

P3.1.4 says "30 px of tabs and a 1 px border, as the kit's tool strip today". Today's tool strip
measures 28 px of tabs plus a 1 px border (the kit's `.e68-tabs--tool .e68-tabs__tab` is 28 px
tall); `SimWorkspace.tsx` subtracted 31 px (`TAB_STRIP_HEIGHT`) from the tool area, so today's tool
group was `split - 2 px` tall. The dock's strips are 29 px, and the default tool group keeps today's
arithmetic (`split - 31 + 29`, `ui/dock/sizes.ts` `LEGACY_TOOL_STRIP`), so that the Output panel is
where it was to the pixel.

## 5. The line below the Registers panel, and above the tool group while Output is collapsed

FlexLayout puts a splitter between any two groups of a column. Today there is none below the
Registers panel (a 1 px border of the region) and none above the tool tabs while the Output panel is
collapsed. The dock makes those splitters inert (no `separator` role, `tabindex=-1`,
`aria-hidden`, no pointer, drawn in `--c-border` as today's line) while the Registers group is sized
by its content and, in the default arrangement, while Output is collapsed. Box differences that
remain, all within the 1 px of the acceptance: the Registers region is 1 px shorter (its border is
now the splitter; everything below it is where it was), and with Output collapsed the tool group
starts 1 px lower.

## 6. The Output panel's strip in the narrow default (P3.1.4)

P3.1.4's rule shows a strip on a locked group only when it holds two panels, a tool panel or a
viewer. Today's narrow layout always shows the strip with the Output tab, also without tool panels.
To keep today's look, the dock shows the strip of the group that holds Output in the simulator's
narrow default arrangement (`DockEngine.stripFor`).

## 7. Unlocked, the editor's message list keeps its height below its strip (P5 N1 acceptance)

The acceptance says that unlocked each group's outer box is today's box within 1 px, except the
Registers group and the groups below it. The editor's Messages group is the other content-sized group
(P3.1.5): today it is 5, 87 or 7 px, which cannot hold a 29 px strip. The dock treats it like the
Registers group: unlocked, the group is the rule's height plus its strip, and the Editor group above
it has the rest. `check-dock.mjs` checks exactly that.

## 8. The splitters' keys and values (P2.2, P3.1.1)

FlexLayout's splitters move 10 px with the arrow keys and report `aria-valuenow` as a percentage
(`aria-valuetext` `<n>%`), where the kit's Splitter reported pixels. The dock adds the kit's other
keys to the default arrangement's splitters (today's four): Shift+arrows 50 px, Home and End the
limits, Enter and a double-click the default. Splitters of a changed arrangement have FlexLayout's
arrows only.

## 9. Splitter names "also after a move" (P5 N1 acceptance)

A move makes the arrangement changed, and P2.2 names the splitters of a changed arrangement
`Resize <panel> and <panel>`. The check therefore asserts today's names in the default arrangement,
after a tab switch, a splitter drag and a font change; after a move, the `Resize A and B` names; and
today's names again after `Reset Layout`. The names survive FlexLayout's renders (no fallback to the
plain `Resize` was needed).

## 10. Reading order: FlexLayout's internal order of the tab layer (P3.1.8)

FlexLayout 0.11.1 renders every tab's content in one flat layer, in the order the tabs were first
rendered, so after a move the DOM order of the panels no longer follows their places. The dock puts
that layer back into reading order after each change of the arrangement by setting the order
FlexLayout keeps (`LayoutController._orderedTabIds`, reached through `Model.getLayouts()` and
`ModelLayout.getController()`) and asking it to redraw: React then moves the elements, so no DOM node
is moved outside React. A focused element that the move blurred gets the focus back. These are
internals of the pinned 0.11.1 (R1); if they are missing the dock leaves the order as it is.
`check-dock.mjs` compares the DOM order with the tree in three arrangements per mode.

## 11. Chained models (no remount on rebuilds)

The dock rebuilds its model with `Model.fromJson(json, previous)` (Reset Layout, a lock change, the
narrow switch, a hidden or shown panel), which adopts the tab elements, so no panel is remounted.
FlexLayout's `Layout` keeps its components only when the new model was adopted from the one it
rendered last; when two models replace each other before React renders, the dock sets the new
model's `adoptedFromModel` (an internal field) to the rendered one. The mount counters of
`check-dock.mjs` (program) show every panel mounted once.

## 12. Roles of the groups' contents (P3.1.8)

FlexLayout's `.flexlayout__tab` is always `role=tabpanel` with `aria-labelledby` its tab button. The
dock removes both from a group shown without a strip (no tab button exists there), so the panel's
`PanelRegion` is a plain `region` as today, and puts them back when the group shows its strip. A
viewer's own element (`data-e68-panel="viewer:<n>"`) is its tab panel; the outer element then has no
role. The tool group's tab list keeps today's name `Tool panels` (set on the element; P2.2's
`name` attribute would need an action after each move).

## 13. The dialog's access keys: `P&lace:` (P3.1.4)

P3.1.4 draws the dialog with `&Panel:` and `&Place:`, two access keys on the letter P. The second is
`P&lace:` (`features/layout/texts.ts`). Tab goes from the chosen place to that place's own lists
(document order); a list keeps Enter for itself, so OK is reached with Tab or a click.

## 14. Drop places and the Output panel's 160 x 120 px (P2.2 `setOnAllowDrop`)

FlexLayout's drop outline for a drop on a group's strip is a 3 px marker, and for a drop into the
middle of a group the group's box. The dock judges a drop into a group (middle or strip) by the
group's box and a drop beside a group or at an edge by FlexLayout's outline (the place the panel
would get). A drop before the first tab of a strip needs the tab not to start at the strip's very
edge (FlexLayout's `restrictAtStripStart`), so the strip has 1 px before its first tab.

## 15. Focus after closing a panel with the Delete key (P3.1.8)

FlexLayout's Delete on a tab moves the focus to the next tab button before it asks to delete the tab.
The dock then moves the focus into the panel of the group's selected tab (or the Editor or Registers
panel when the group is gone), as P3.1.8 says.

## 16. The Output panel's collapse button inside a tab strip

`features/output/output.css` hides the collapse button inside a `tabpanel` ("As a tab of the narrow
layout the panel cannot be collapsed"). With the dock, the Output panel is a tab panel wherever its
group shows a strip: unlocked, or moved into a group with other panels. There, as in today's narrow
layout, it cannot be collapsed; `hidePanel('output')` still collapses it and the dock draws the
expand bar in its tab (P3.1.5). Locked in the default wide arrangement nothing changes.

## 17. Transient tabs and the mode (P4.4)

P4.4 lists "a mode change" among the ways a transient tab goes away. The Editor dock closes every
viewer (running its `onClose`) when the mode leaves Editor mode. `openTransient` before the Editor
dock attaches is queued (both docks attach at start, so the queue matters only before the first
render, `?open=` and start-up arguments).

## 18. `EditorWorkspace.tsx` and `SimWorkspace.tsx` are deleted (P5 N1 Changes)

Their rules moved into `ui/dock`: the message-height rule of `EditorCenter` (`ui/dock/sizes.ts`
`editorMessagesHeight`, `EDITOR_MIN_HEIGHT`), the content-sized Registers region
(`DockWorkspace.tsx` `RegistersContent`), the Output expand bar (`OutputContent`), the narrow switch
(`DockWorkspace.tsx`, the same media query at `NARROW_WIDTH`). Nothing imported them except
`Shell.tsx`. `SplitPane.tsx` stays (the Help drawer's `useSplit` and `useElementSize`).

## 19. Splitter colour (P3.1.8)

P3.1.8 maps the splitters to `--c-border-strong` (controls, 3:1). Today's splitter line is
`--c-border`. The dock follows P3.1.8 for every splitter that is a control; the inert lines of entry 5
keep `--c-border`. The boxes are unchanged.

## 20. The View menu's panel commands have no shortcut

The acceptance item "every View menu command and its shortcut shows and focuses its panel" is checked
for the commands; `commands/tables/keys.ts` binds no chord to `sim.view.*` (F2 and Ctrl+Tab cycle the
panels, checked separately). `check-dock.mjs` prints a note.

## 21. `state/dock.ts` additions (P4.4: "N1 may add members")

`DockController.stats()` (action and mount counters for the browser check), and the exports
`attachDock`, `DockLive`, `DockAttachment`, `dockModeOf`, `lockedIn`, `withLocked`, `TransientSpec`,
`DockMoveTarget`, `DockMode`, `DockStats`. The stub's members keep their signatures. `locked()` and
`setLocked()` work without a mounted dock (they read and write `layout.dock.locked`).
