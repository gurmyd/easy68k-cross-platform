# Errata of work package B1 (EASyBIN)

Where the code of B1 differs from ARCHITECTURE.md, or the document leaves a gap that B1 had to fill.
The specification of EASyBIN itself is `docs/porting/easybin.md` (written by B1). Entries under
"Contract" ask W1 for a change of `app/src/contracts/`.

## Document

1. **1.3.8, Save Binary shortcut.** The table says "(as found in the source)". The source has
   `ShortCut = 16467` = Ctrl+S (`Form1u.dfm`, action `SaveBin`); macOS Cmd+S (and Ctrl+S) by rule K2.
   W3's `tables/keys.ts` already binds exactly that. The help page's "Save Binary... Ctrl+B" is wrong
   (easybin.md 18).
2. **1.3.8, File > New.** "fill memory with the Fill byte" comes from the help page. The source fills
   with `$FF`, after the question `The current environment will be lost, click OK to continue.`
   (caption `Caution`, OK / Cancel) (`Form1u.cpp:352-381`; easybin.md 9).
3. **1.3.8, "Binary Output Split".** The caption is ` Binary Input/Output Split ` (`Form1u.dfm`,
   `OutputSplit`).
4. **1.3.8 is to be extended** (its text says B1 does it, but ARCHITECTURE.md belongs to the
   architect). The complete rows are in easybin.md 21.4, for the architect or DOC1 to copy. Besides the
   six File items they add Help > EASyBIN Help (F1, Help panel), Help > About EASyBIN, the workspace
   controls, the window title, F1 in the About box, dropped files, the tab order and the dropped
   command line.
5. **2.7, dialog ids.** B1 adds `easybin.about` (Help > About EASyBIN). H1's About components cannot
   be imported by another feature (3.12.3), and the EASyBIN box has its own texts.
6. **9.4 B1, "S-record files written by the assembler load and save back byte for byte where the
   original would".** Read as: after loading such a file, every value in memory and every field is the
   original's, and the file Save S-Record writes is byte for byte the file the original writes for the
   same From, To and Start Address. It is not the input file: the original writes its own header,
   32-byte records and an S7 record (easybin.md 11.3). Proven against the original's own functions
   compiled natively (easybin.md 0.4) on the port's engine output and on the official assembler's
   outputs in `build/ground-truth/asm`. Of the latter, the 604 files made from the sources of the one
   third-party project that this work may not use are excluded; 369 files (178 distinct) are compared.
7. **1.3.3 / bootstrap window title.** The original's title is the opened file's full path after an
   open and `EASyBIN v2.5.0` after New. `windowTitle()` in `bootstrap.ts` (W3) shows the fixed title
   in EASyBIN mode and `AppState` has nowhere to carry the file name (Contract C2). B1 shows the
   original's caption in EASyBIN mode's status bar (region `status`, mode `easybin`) and asks for the
   window title in `docs/requests/B1-window-title.md`. **Resolved at gate I1, round 2:** the shell's
   `setModeTitle(ctx, mode, title | null)` (`state/shell.ts`) exists; `followCaption` in
   `features/easybin/commands.ts` (started by the feature's `init`) sets it to the caption after
   every open or drop and to null after New. The status-bar panel is gone; EASyBIN mode has no status
   bar text, as the original has no status bar.
8. **F1 in EASyBIN mode (2.9.1, 2.9.2).** `tables/keys.ts` binds F1 to `ed.help.help`,
   `ed.help.context` and `sim.help.context` only, so the dispatcher has no F1 in EASyBIN mode. The
   original opens `easybin.htm` on F1 in the memory area and the Address field (easybin.md 15.2).
   Local guard until W3 adds the binding (`docs/requests/B1-keys.md`): those two elements handle an F1
   that reaches them by running `bin.help.help`. Once the chord exists the dispatcher consumes F1 first
   and the guard never runs. **Resolved at gate I1:** W3 binds F1 to `bin.help.help`; the local F1
   cases were removed in round 2 (the Address field also skips keys the dispatcher already consumed).
9. **`bin.help.help`** runs H1's `ed.help.help` with the page `easybin.htm` (the argument H1 offers,
   `docs/requests/H1-help-from-dialogs.md`), because a feature cannot import H1's `openHelp`. The
   registry does not check a command's mode for `run`, so this works in EASyBIN mode. F1 in the About
   box (the credits page in the original) runs `ed.help.help` with `credits.htm` and the run option
   `allowInModal` that W1 added at gate I1 (`aboutBoxKey` in `commands.ts`; the About box listens
   on the window while it is open, because the kit's `Dialog` takes no key handler).
10. **Exit (1.3.8 had no decision).** `bin.file.exit` ends the application like `ed.file.exit` and
    `sim.file.exit`: the editor's close prompts, the simulator's log and program files closed, then
    quit (desktop) or the exit screen (web). easybin.md 22 item 1 asks the architect to confirm.
11. **Files dropped in EASyBIN mode (3.8.5 says nothing).** FS1's window listener ignores drops in
    EASyBIN mode. B1 adds its own capture listener on the window, active in EASyBIN mode only, and reads
    the dropped files' bytes directly: EASyBIN needs bytes and a name for its caption, not a stored
    copy, so nothing is written to the browser store.
12. **The tab order** of the original (Length before First Address, the Copy and Fill rows before the
    From/To row) is not reproduced; the port's follows the layout (easybin.md Q18).
13. **Fixture names and line ends (gate I1).** The fixture with a zero byte inside an S-record line was
    called `nul.S68`; NUL is a device name Windows reserves with any extension, so git could not open
    it and a Windows checkout would fail. It is `fixtures/zero-byte.S68` now (the scripts and the
    oracle's transcript name it so; the bytes are unchanged). The root `.gitattributes` gives `/app/**`
    `text=auto eol=lf`, which would have turned the fixtures' CR LF into LF on commit (measured:
    `asm-hello.S68`, 192 bytes on disk, would be stored as 187), breaking every byte-for-byte
    comparison on a fresh checkout. `app/src/core/easybin/fixtures/.gitattributes` (`* -text`) keeps
    them as bytes, as the engines' own `.gitattributes` do. `core/easybin/file-names.test.ts` checks
    both: no reserved or case-colliding names in B1's folders, and `git check-attr text` = unset for
    every fixture.
14. **Gate I1, round 2: the round-1 report was wrong about `overwritePrompt`.** It said the field was
    still missing from `contracts/fs.ts`; W1 had added it in round 1 (`SaveRequest.overwritePrompt?:
    OverwritePrompt | null`, W1 errata entry 11). B1 now uses the plain `SaveRequest` (Contract C1).
    The same report said the browser check polls after saves; two of those waits used
    `page.waitForFunction` with an async predicate, which returns a promise that counts as truthy at
    once, so they did not wait (independent review of round 1). They poll inside `page.evaluate` now,
    and the check proves at its start that the wait after a save waits for a write made 400 ms later.
15. **The kit's `e68-sr`** replaces B1's own copy of the screen-reader-only rule
    (`.e68-easybin__status`) for the memory area's live description.

## Contract

C1. **`SaveRequest` has no `overwritePrompt`** (FS1's errata C2 asks for it). The original asks
    `File exists! OK to replace?` (caption `Alert`) itself after the dialog, and for Save Binary about
    four derived names the dialog never sees. B1 passes `overwritePrompt: null` (FS1's dialogs then
    ask nothing) with a local type `SaveRequest & { overwritePrompt: null }`, and asks the original's
    question itself. With a `FileDialogs` that ignores the field, the user would be asked twice.
    Request: the optional field of FS1's C2, with `null` meaning "ask nothing". **Done by W1 at gate
    I1** (`contracts/fs.ts`); B1 uses the plain `SaveRequest` since round 2.

C2. **No place for EASyBIN's window caption in `AppState`.** Request: `AppState.easybin: { caption:
    string }` (or a title hook in the shell), so that `windowTitle()` can show the opened file in
    EASyBIN mode as it shows the loaded program in Simulator mode. B1 keeps the caption in its own model
    until then (entry 7). **Declined by W1 at gate I1** in favour of the shell's `setModeTitle`, which
    needs no contract; B1 uses it since round 2 (entry 7).
