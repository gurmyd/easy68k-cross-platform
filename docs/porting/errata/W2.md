# Errata of W2 (Design tokens and component kit)

Corrections to `docs/ARCHITECTURE.md` found while building W2 (section 8, "Corrections to the
specs"). Each entry says what the document says, what the repository does, and why. None of them
changes a contract of section 3.

## 1. `--c-border-strong` fails the 3:1 rule of 2.8 in both themes

- Says: 2.8, `--c-border-strong` = `#9CA3AF` (light) / `#545D68` (dark), "field borders"; and,
  in the same section, "interface graphics at least 3:1, in both themes".
- Measured (WCAG 2 contrast): light `#9CA3AF` is 2.31:1 on `--c-bg`, 2.54:1 on `--c-surface`,
  2.43:1 on `--c-panel`; dark `#545D68` is 2.76:1, 2.48:1, 2.25:1. A field border is the
  visual information that identifies the field (WCAG 1.4.11), so both values break the rule.
- Does: light `#818B98` (3.14 / 3.45 / 3.31:1), dark `#6E7781` (4.06 / 3.64 / 3.30:1). Same hue
  family, the smallest change that passes on all three backgrounds.
- Checked by: `app/src/styles/contrast.test.ts` (part of `npm test`).
- Proposed text for 2.8: `--c-border-strong` | `#818B98` | `#6E7781` | field borders.

| `--shadow-popup`, `--shadow-dialog` | | | menus, tool-tips, toasts; dialogs |

## 3. The gutter dots need an outline to meet 3:1 (for U1)

## 4. The gallery at `?gallery` needs one line in `main.tsx`, which W3 owns

- Says: 9.1 W2, outputs include "a gallery page at `?gallery`".
- Situation: the page is served by `app/index.html` -> `app/src/main.tsx`, and `main.tsx` belongs
  to W3 (section 8, W0 erratum 4). W2 may not edit it.
- Does: W2 delivers `app/src/ui/components/gallery/route.ts` (`galleryRequest(location.search)`)
  and `mount.tsx` (`mountGallery(container, request)`); `docs/requests/W2-gallery-route.md` asks
  W3 for the three lines in `main.tsx`. Until then the gallery is served by the Vite dev server at
  `/src/ui/components/gallery/gallery.html` (development only; the production build contains
  only `index.html`), which is also what the browser check uses.

## 5. Keyboard acceptance is checked in a browser, by a script in W2's folder

- Says: 9.1 W2 acceptance, "keyboard behaviour of menu bar, toolbar, tabs and dialog follows
  2.11"; "the gallery has no serious finding in an automated accessibility scan in both themes";
  section 0 rule 5 and `app/vitest.config.ts`: unit tests run under Node with no DOM.
- Situation: keyboard behaviour cannot be shown without a DOM; the browser suites

  behaviour and the axe scan run in headless Chromium and WebKit through
  `app/src/ui/components/gallery/check-gallery.mjs` (142 checks).
  `docs/requests/W2-gallery-check.md` asks for it in CI (or for Q1 / X1 to adopt it).

## 6. "Dialogs are `dialog` elements" (2.11) is implemented with the ARIA role

- Says: 2.11, "Dialogs are `dialog` elements with `aria-modal` where modal".
- Does: `Dialog` renders a `div` with `role="dialog"` (`role="alertdialog"` for message boxes),
  `aria-modal="true"` when modal, `aria-labelledby` its title, and its own focus trap - not the
  HTML `<dialog>` element with `showModal()`.
- Why: `showModal()` puts the dialog in the browser's top layer, above every `z-index`, which
  breaks the stacking order of 2.8 (`--z-menu` and `--z-toast` above `--z-modal`) and hides
  pop-ups (menus, lists, tool-tips) that a dialog opens. Read "dialog elements" as "elements with
  the dialog role"; the accessibility tree is the same.

## 7. MaskedField: details the specs leave open, and one rule taken from the spec over VCL

hardware §12 V1 marks the keystroke-level behaviour of the masked edits UNVERIFIED. The kit
implements (`app/src/ui/components/masked.ts`, unit-tested):

- Delete clears the position at the caret and leaves the caret where it is; Backspace clears the
  position before it and moves onto it; with a selection both clear the selection.
- A key at the end of a full field is refused (beep).
- AutoSelect as in the DFMs: the register fields select their text on focus (VCL default), SR does
  not (`AutoSelect = False`, `SIM68Ku.dfm:733`), nor do the Hardware panel's fields
  (`hardwareu.dfm:1783` and the others). This is the `autoSelect` prop; the owners pass it.
- SR Backspace: sim-ui §4.4 says Backspace "types a `0` at the caret". In the VCL, `TMaskEdit`
  also handles `VK_BACK` in its own `KeyDown` (clearing the position before the caret) before the
  `OnKeyPress` handler turns the `#8` into `'0'`; if so, the original's net effect would be "the
  position before the caret becomes `0` and the caret does not move". The VCL source is not in the
  reference tree, so the kit follows the spec. Proposed: confirm under Wine (T3) and correct
  sim-ui §4.4 or `masked.ts` (`SR_FIELD.backspace`).

## 8. `components.css`

- Says: 2.8, "Plain CSS only: `tokens.css`, `base.css`, `components.css`, and one `.css` file next
  to each component."
- Does: `components.css` holds the classes several components share (field frame, pop-up
  surface, access-key underline, screen-reader-only text, separators, icons); each component's
  own rules are in its `.css` file. `app/src/styles/index.ts` imports the three global files once
  (the entry point imports `./styles`).

## 9. Tool-tips have no layer of their own in 2.8

Tool-tips use `--z-toast` (the top layer of 2.8), so a tool-tip of a toast or of a menu is not
covered. No new `--z-*` value was added.
