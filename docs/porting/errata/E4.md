## Format (the settings files)

### 1. The style attributes and `$highlight disabled` are read with `atoi`, not as on/off lines

- Says: editor-ui §11.4 rule 3, "On/off lines must have exactly one character before the `$`:
  `1` = on, anything else = off", and the table gives lines 22-54 the type "int, 0/1 x3".
- Source: `optionsS.cpp:500-870` reads `$code bold` and its 23 neighbours and `$highlight
  disabled` with the value scan and `atoi(temp)` into a `bool`: any non-zero number is on (`2`,
  `-1`, ` 1`), `x` is off. Only the lines read with `&buffer[1]` (2-9, 12, 14-17, 55) follow rule 3.
- Does: as the source (`settings-dat.ts`). Proposed text for §11.4 rule 3: "... The style
  attributes (lines 23-25, 27-29, ... 51-53) and line 54 are numeric: `atoi` of the text before
  the `$`, any non-zero value is on."

### 2. A missing line does not put the last setting back to its default: `$color presets` becomes 0

- Says: editor-ui §11.4 step 2 and ARCHITECTURE.md 3.10, "a missing line puts all later lines back
  to defaults".
- Source: the reader keeps one `char buffer[257]` for the whole file and never clears it. With one
  line missing, the read for line 57 hits the end of the file: `getline` stores only a NUL at
  `buffer[0]` (C++98 27.6.1.3: no character extracted, a null character is stored in any case), so
  the buffer holds `\0$color presets` from the file's real last line. The value scan passes the
  NUL, finds that `$`, `strcmp` matches, `temp` is empty and `atoi` gives 0: the item `Color1`.
  The same happens with an extra line removed anywhere and with more than one missing line.
- Does: as the original (`c-reader.ts` models the buffer and its leftovers). With one line missing
  every later setting is its default except `colorPreset`, which is 0 instead of -1. In the port
  this changes nothing that is drawn (both show the stored styles); only the Color Presets box
  reads `Color1` instead of nothing. In sim68K.dat the same effect reads the stale
  `$disable display` line with a NUL as its value, which gives off, the default anyway.
- Proposed text for §11.4 step 2: "... all later settings fall back to defaults, except line 57,
  which then matches the leftover of the file's last line and selects `Color1`."

### 3. What C does to the lines, reproduced

`c-reader.ts` applies the original's C operations to bytes. Details the specs leave open:

- Text mode: CR LF becomes LF; a lone CR is part of the line (and makes the name not match).
- A line of more than 255 bytes puts the stream into its fail state: the line is seen truncated
  to 255 bytes and every later line reads as empty (C++98 `getline`); a line of exactly 255 bytes is
  read whole.
- A NUL inside a line ends it for `strcmp` and for `temp`; the value scan itself walks past it to
  the `$`. A scan that finds no `$` in its line runs on into the bytes an earlier, longer line left
  in the buffer (`while (buffer[index] != '$' && index < SIZE)`).
- `atoi` past 32 bits wraps (unverified on the binary; no realistic file has such a value).
- The first contents of the buffer are unknown in the original (stack memory); zero here. Only a
  file whose first line has no `$` could observe the difference.
- Ctrl-Z (0x1A) is not treated as an end of file (the C runtime's text mode may; unverified).

### 4. Values the port keeps as numbers

The original stores some values as control text; the contract (3.10) keeps numbers. A line whose
text the port cannot turn into its number is treated as a line that did not match (the setting
keeps its default), because the original would fail on it later or show garbage:

| Line | Original | Port |
|---|---|---|
| settings.dat 11 `$font size` | `cbSize->Text = temp`; a non-number raises in `StrToInt` at the next New | a whole number 1..9999 (blanks around allowed) |
| settings.dat 13 `$fixed tab size` | `FixedTabSize->Value = atoi(temp)`, the TCSpinEdit clamps to 4..20 | the same (`abc` -> 0 -> 4) |
| settings.dat 57 `$color presets` | `ItemIndex = atoi(temp)`; outside 0..4 no item is selected | the same: -1 |
| sim68K.dat 14, 23-26 addresses | the text into a TMaskEdit `aaaaaa` | one to six hexadecimal digits |
| sim68K.dat 19 `$which stack` | `ItemIndex = atoi(temp)`; outside 0..8 no item | outside 0..8: the default 8 |
| sim68K.dat 29, 31, 33 font sizes | `Font->Size = atoi(temp)` | a size above zero |
| sim68K.dat 36 `$auto trace interval` | `UpDown1->Position = atoi(temp)`, kept within 10..1000 | the same |

A font name is taken as it is, also the Output Window Font, whose list the port limits to the
metric fonts of 3.5.1 (1.4 note 27): what the text screen does with a name outside that list is
SH3's (it falls back to its default).

### 5. Window lines written on export

- Says: ARCHITECTURE.md 3.10 and 1.4 note 21, "written with the original's defaults on export".
- settings.dat: `$maximized edit` 0, `$main top` 106, `$main left` 513 (editor-ui §11.4 "Default
  when the file is missing"). The original's default height and width are two thirds of the
  screen, which is unknown here; the shipped file's 943 and 925 are written.
- sim68K.dat: def.h:252-262 (`FORM1_TOP` 100, `FORM1_LEFT` 100, simIO 300 / 200, memory 80 / 280,
  stack 200 / 40 / 538, hardware 100 / 240), the main window's design-time size 744 x 500
  (SIM68Ku.dfm; its position is `poDefault`, so `FORM1_TOP` / `FORM1_LEFT` stand in), `$simIO
  visible` 1 (always visible) and the full-screen monitor byte 0 (initSim() resets it).
- The import of sim68K.dat shows a panel whose line says `1` and hides the other two (a missing or
  out-of-step line is "hidden", the original's start-up state). Line 11 is ignored.

### 6. The import sets every setting the file holds

`editorSettingsFromDat` and `simSettingsFromDat` return every setting of the file, from its line
where the line matched and from the original's start-up value otherwise (positional rule). The
original's start-up value of `colorPreset` is -1 (none selected); the port's own default is Auto
(5), which no file holds. The port's own settings (`template`, `lineNumbers`, `speed`,
`highlightChangedRegisters`) are never touched by an import of the `.dat` files.

## Behaviour (the dialogs)

### 7. "Cancel restores everything" with several windows: what "everything" is

- Says: 1.4 note 8, "Cancel restores everything". 3.8.6: windows share one set of settings.
- Decided: a dialog keeps what the user changes in a draft (the values of the controls the user
  touched) and writes nothing before OK. The controls show the draft over the live settings, so an
  untouched control follows a change another window makes while the dialog is open. Cancel,
  Escape and the close button discard the draft: every setting is afterwards what it would be had
  the dialog never been opened, which includes changes other windows made meanwhile ("everything"
  = everything this dialog changed). OK writes the draft and nothing else, through
  `ctx.settings.update`, so another window's change to any other setting survives. A snapshot
  restored on Cancel would have undone those other windows' changes, and a snapshot written on OK
  would have reverted them.
- The font and size boxes count as touched from the moment the dialog opens (entry 8). In the
  original the boxes themselves are the defaults: new documents take `cbFont->Text` and
  `cbSize->Text` (`textS.cpp:826-827`), the settings file stores them (`optionsS.cpp:166-167`), and
  OK applies them to the active document (`editorOptions.cpp:83-86`); they open on the active
  document's font (1.4 note 8). So OK always makes that font and size the defaults for new documents, also when
  the user left the boxes alone and another window changed the default meanwhile. This is the
  original's behaviour (fidelity first), not an exception to "only touched settings": in the
  original those two boxes are always applied. Test: `options.test.ts` ("OK always makes the boxes'
  font and size the defaults ...").
- Consequence, recorded in `docs/differences/E4.md`: what the original applies at once (Auto
  Indent and Real Tabs on click; the Assembler Options check boxes read directly by Assemble) takes
  effect on OK.
- Tests: `options.test.ts` ("Cancel restores everything ... with another window writing
  meanwhile"), and in a browser with two real windows `check-options.mjs`.

### 8. The font and size boxes of Editor Options

- OK makes the shown font and size the defaults for new documents ("New Font", "New Font Size") and
  gives them to the active document, as the original does. They start from the active document
  (font mapped to one of the three; size: the real size, note 8), so OK without touching them makes
  the active document's font the default, as in the original.
- Note 8 fixes only the opening value. When the user chooses another font, the size box shows the
  document's size if that font lists it, else the original's bucket (`cbFontChange`). The size
  list holds the font's sizes plus the shown size if the font lacks it (a trailer can carry any
  size). The original's boxes are editable combo boxes in which any text can be typed (and a
  non-number then fails in `StrToInt` with `Error in NewProject()`); the port offers the lists.
- The tab type and tab size controls show the defaults, not the document's (the original does not
  re-synchronise them), and OK gives them to the active document.

### 9. A preset chosen while an attribute box is checked (GUI defect, not reproduced)

- Source: `SyntaxComboChange` clears `Bold`, `Italic` and `Underline` with `->Checked = false`. A
  VCL check box fires `OnClick` when `Checked` changes in code, and `BoldClick` then runs
  `setSyntaxPreviewStyle()`, which sets `SyntaxCombo->ItemIndex = 3`; back in `SyntaxComboChange`,
  `if (SyntaxCombo->ItemIndex == 3) return;` leaves before the preset is applied. So in the original,
  choosing Color1, Color2, No Color or Disabled while one of the three boxes is checked selects
  Custom and changes no colour. Typing into the (editable) preset box fires `OnChange` with
  `ItemIndex` -1, the `default:` case, which applies Disabled.
- Does: neither is reproduced (section 0 rule 1: a GUI defect that cannot change a program's
  results). The preset box is a list; a preset always applies as editor-ui §11.2's table says.

### 10. Smaller decisions

- **Auto** is the sixth item of the Color Presets list, after the original's five (1.5, note 19).
  Choosing it stores the Color1 values (core/highlight `presetStyles`, E3) and turns highlighting
  on; with -1 (none selected, e.g. after importing the shipped file) the box shows an empty item.
- **Custom** chosen alone changes only the preset index, not `highlightDisabled` (the original does
  not set `styleChange` for it, and its preset index is saved at exit).
- A swatch or an attribute box with no element selected (or Background, for the boxes) changes no
  style but counts as a change: the preset becomes Custom and highlighting is turned on, as in the
  original.
- **Save Template** writes `EditorSettings.template` at once; OK and Cancel neither save nor undo
  it (optionsS.cpp:126-130). The box is loaded every time the dialog is shown and is drawn in the
  Editor Options font (the stored default, not the dialog's pending choice).
- **Assembler Options** asked for while it is open comes to the front (focus) instead of opening a
  second one; it shows its first tab when it opens.
- **Editor Options** is enabled while a document is open (state E of editor-ui §2.7, as the store's
  `documents.activeId`).
- The **preview** is drawn with the shown styles; under Auto with the palette of the theme in force
  (2.8). It is an image to assistive technology (`role=img`), because its colours are the original's
  whatever their contrast; the browser check's accessibility scan excludes it.
- **F1 in Assembler Options** (modeless) opens `options.htm` (gate I2): the dialog's box carries
  `data-e68-own-keys="F1"`, so the shell's key dispatcher leaves F1 to the dialog while the focus is
  anywhere in it (`commands/keymap.ts`, errata W3.md entry 37; `docs/requests/E4-dialog-help-key.md`).
  The kit's `Dialog` passes no attributes through, so the dialog sets the attribute on its box from
  an effect. F1 and Help in the modal Editor Options open `options.htm` above the dialog
  (`run('ed.help.help', 'options.htm', { allowInModal: true })`).
- **settings.transfer** is the port's own dialog (no original): one row per file with `Import...`
  and `Export...`, a status line and `Close`. An import takes effect at once and has nothing to
  cancel. Export suggests `/browser/<name>` (the desktop app: the user-data folder); the filters are
  `Settings File  [.dat]` / `Template File  [.NEW]` and `Any File  [*.*]`.

### 11. template.NEW gets no line break after its last line unless the text ends with one

- Source: the Template box is a `TRichEdit` with `PlainText = True` (`optionsS.dfm:209-214`), the
  same kind of control as the source window, and `Save Template` calls its `Lines->SaveToFile`
  (`optionsS.cpp:128-129`). editor-ui §6.7 says of that save: "a line break after the last line is
  written only if the text itself ends with one". (A `TMemo`'s `TStrings.SaveToFile` would add one;
  the box is not a memo.)
- Does: `templateToBytes` turns each line break into CR LF and appends nothing, so `x` is written as
  `x` and `x` + line break as `x` CR LF; the shipped template, which ends with a line break, writes
  back byte for byte. Test: `template.test.ts` ("adds no line break after the last line ...").
  Unverified on the binary (Wine is not set up on this PC).
