# Errata of N9 (end-to-end tests of the stage of additions)

Package N9 (ARCHITECTURE-PLUS P5 N9): `tests/e2e/plus/**` and the new helper file
`tests/e2e/fixtures/plus.ts`. No existing helper or spec was changed.

## 1. Files besides the four spec files the entry names

P5 N9 names `layout.spec.ts`, `files.spec.ts`, `history.spec.ts` and `viewer.spec.ts`. The acceptance
also asks that "everything above works with the network cut", so the scenarios are written once as
functions in non-spec modules (`student.ts`: the long scenario; `windows.ts`: the two scenarios with
two windows; `arrangement.ts`: the moved panels) and run twice: online by `history.spec.ts` and
`layout.spec.ts`, and after `reloadOffline` by a fifth spec file, `offline.spec.ts`. All are below
`tests/e2e/plus/`, which N9 owns. The helpers the specs share are a new file,
`tests/e2e/fixtures/plus.ts` (P5 N9: "tests/e2e/fixtures/** where the new specs need helpers"; X1's
rule "add, do not change").

## 2. The PDF's blob is read without `fetch`

P3.4.2 says automation checks "that the iframe exists with a `blob:` of type `application/pdf`
holding the file's bytes". The production policy's `connect-src` does not allow `blob:`, so a `fetch`
of the frame's URL from the page is refused (WebKit: "Refused to connect to blob:... because it does
not appear in the connect-src directive") and logs a console error. `watchBlobs()` therefore wraps
`URL.createObjectURL` in the page before the viewer opens and keeps each Blob by its URL; `blobOf()`
reads the very Blob whose URL is the frame's `src`. Nothing of the application is called.

## 3. Where a browser shows no PDF

Playwright's default Chromium (the headless shell) reports `navigator.pdfViewerEnabled === false`
(docs/requests/N0.md 5.1); P3.4.2 says the viewer then shows the notice with `Export` instead of the
frame. The long scenario asserts the frame (and the blob's type and bytes) where the browser reports a
PDF viewer, and the notice text where it does not; in both cases `Export` must give the file's bytes.
Nothing is skipped. Playwright's WebKit reports a viewer and gets the frame (it draws nothing in it on
Windows, N0 erratum 6, which is not something a test can see).

## 4. Reopening a saved `.X68` adds one empty line

The texts compared after a reload or a restore are `text + "\n"` (`reopenedText` in `student.ts`):
Save writes CR LF before the four trailer lines and the original's load removes only the four lines
(`core/documents/format.ts`, `stripTrailer`, textS.cpp:139-173). This is the original's behaviour,
not a defect of the stage.

## 5. "The second version"

The acceptance says "restores the second version from Earlier Versions". The test restores the second
save, which is also the second row of the list (newest first: save 3, save 2, save 1, as opened).

## 6. The parity matrix rows of the stage's commands

N10 adds six rows for the stage's commands to the table of `docs/ARCHITECTURE.md` 1.5. Their rows in
`tests/parity/matrix.json` (status `+`) point at the tests of `tests/e2e/plus` that run each command:
`Move Panel To...` and `Lock Layout` / `Reset Layout` at `layout.spec.ts` (and `offline.spec.ts`),
`Earlier Versions...` and `Trash...` at `history.spec.ts` (and `offline.spec.ts`), `Port Additions...`
at `viewer.spec.ts`. No end-to-end test runs `Split Editor Right`, `Split Editor Down` or `Close Split`;
their row is of the kind `unit` and names N2's tests (`app/src/features/editor/commands.test.ts`,
`app/src/ui/editor/split.test.ts`). The rows hold only together with N10's change of the document.
