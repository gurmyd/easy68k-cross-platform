# Errata and notes of work package U3 (Advanced breakpoints)

Where the code of `app/src/core/breakpoints/` and `app/src/features/breakpoints/` differs from
ARCHITECTURE.md or the specs, or decides something they leave open. The deliberate differences
from the original's window are in docs/differences/U3.md.

## Contract

No member was missing. The panel uses `SimEngine.setBreakCondition`, `setBreakExpression` and
`setBreakCounts` (through `RunController.invoke`), `SimSession.onEngineReplaced` and
`DialogService.messageBox`. No local adapter.

## Specs

### 1. `Count = 00`: sim-ui §12.2 and sim-core §7.3 disagree; the source agrees with sim-core

- sim-ui §12.2 (quirk table) and §18 row 11: "`Count = 00` breaks after **every** instruction, even
  when the expression is false".
- sim-core §7.3: "`count == 0` breaks on every step until the expression is first true and never
  afterwards".
- Source (`BPointExpr.cpp:147-149`): `if(isBrk) bpCountCond[id]++; isBrk = (count ==
  bpCountCond[id]); if(isBrk) bpCountCond[id] = 0;`. While the expression is false the counter
  stays 0 and `0 == 0` breaks; the first time it is true the counter becomes 1 and never returns to
  0 until Run resets it. sim-core is right; sim-ui's sentence holds only until the expression is
  first true.
- No code depends on it: the engine evaluates the count. Proposed for the spec owner: replace the
  sim-ui sentence by sim-core's.

### 2. `Entry not stored.  Fields missing.` cannot be produced through the port's editors

- sim-ui §12.2: "If any field is empty: box `Entry not stored.  Fields missing.`".
- In the original only the editable combo boxes could be emptied (the mask edits always hold their
  blank characters, `0`). Note 40 removes editable lists, and the kit's MaskedField always holds
  `width` characters. So no user action leaves a field empty.
- Does: `setEntry()` keeps the test (an empty text or an index outside the list is "missing") and
  shows the message; the unit tests reach it through the model's API (`tables.test.ts`,
  `model.test.ts`). The browser check cannot reach it.
- Corrected at gate I2 (review of U3): Enter in an Expression editor whose expression was empty
  or incomplete reached this message, because `setEntry()` tested the fields before the state of
  `Set`. In the original `Set` is disabled for such an expression (`setExprButtons`), so it can
  never show the message there. `setEntry()` now tests "complete" first and does nothing for an
  incomplete expression; the browser check presses Enter in an empty Expression editor and
  expects no message box.

### 3. Fields the documents leave open

- **Condition `id`**: sim-core §7.2 lists `id` among the fields; `BPoint::isBreak` never reads it.
  The original stores `regCount` / `addrCount` at the time of Set (the 0-based row for a new row,
  the count for an edited one). The port sends the condition's 0-based row within its grid.
- **Register conditions' `readWrite`**: the original never sets it for a register condition; the
  port leaves it out (the binding sends 0).
- **Freed slots**: the original disables the slot a Clear frees (`isEnabled(false)`); Clear All of
  the expressions only sets `exprCount = 0`. The port sends every freed slot disabled
  (`enabled: false`, zero fields, an empty postfix for an expression) and then the counts. The
  engine evaluates only the first `exprCount` expressions, so the effect is the same.
- **Number of rows**: 2.6 does not say; the original's grids have 50 rows including the header,
  so 49 rows can be defined (the engine has 50 slots per table). The port shows and allows 49.

### 4. Which row `Clear` removes

- sim-ui §12.2: "`Clear` removes the selected defined row ...; on an undefined row it shows
  `Select a Valid Row.`".
- Source: a click on a row beyond the defined ones sets the row `Clear` acts on to the last
  defined row (`reg_edit_row = regCount`), so the original's message appears only in rarer states
  (after a Clear of the last row without a new click). The Expression grid's click does not set
  `expr_edit_row` at all.
- Does: as sim-ui says - the selected row if it is defined, the message otherwise. The builder
  field still takes the clamped number (as the source). docs/differences/U3.md entry 10.

### 5. A single click on the grid while editing

- sim-ui §12.2: "A single click on a grid, scrolling it, or dragging a row/column hides the editors
  without storing".
- Does: selecting another row of the same grid (click or arrow keys) hides that grid's editors
  without storing, and Escape does. A click inside the editors, on the edited row's own number,
  and scrolling do not (in the port the editors are part of the row and scroll with it; in the
  original they were separate controls floating over the grid, which is why scrolling had to hide
  them). Dragging does not exist (note 40).

### 6. Confirmation texts (note 40)

- Note 40 asks for "a confirmation" before expressions are removed with a condition but gives no
  text. The port's: title `Break Points`, icon confirmation, OK / Cancel,
  `Expression 2 uses this condition and is removed with it.` /
  `Expressions 1, 3 use these conditions and are removed with them.` (Clear All).
  `features/breakpoints/model.ts`, `confirmText`.

### 7. The application's start is a cold start, and empties the grids

- 4.7.1: "The application's own start is the same function". `onEngineReplaced` therefore also
  fires when the window's first engine exists. The model empties the grids at every
  `onEngineReplaced` (the acceptance item "the grids are empty after a cold start"). Rows entered in
  the panel while the first engine is still being created are therefore lost when it arrives (they
  were sent to the session's stand-in engine, which ignores them). The original has no such moment
  (its window cannot be used before the process has started). The browser check waits for the end
  of the start before it types.

## Kit

### 8. Whole-row editing with the DataGrid

- The kit's DataGrid edits one cell at a time (`editing: { row, column }` with `renderEditor`); the
  original's editors cover the whole row. The panel passes `editing: { row, column: -1 }` (so the
  grid drops `aria-activedescendant` and takes the focus back when the edit ends) and renders the
  editors itself in the columns' `render` of the edited row. Each editor stops `pointerdown` and
  `dblclick` from reaching the grid. Works in Chromium and WebKit (check-breakpoints.mjs). If the
  kit owner prefers, a `rowEditing` mode of DataGrid could replace this; not requested.

### 9. axe `scrollable-region-focusable` on the DataGrid body

- A DataGrid with a `height` scrolls its body while the focus stays on the grid; axe reports the
  body as a serious violation. The check prints it as "not counted (kit)":
  docs/requests/U3-datagrid-scroll-region.md.
- Resolved at gate I2: W2 made the focused grid element the scroll container (errata W2 entry
  20; the request's status line). The check no longer filters this rule: every serious or
  critical axe finding counts.
