# Errata of H1 (Help, examples, About)

What H1 found while building the help import, the Help panel, the About boxes and the examples
from `docs/ARCHITECTURE.md` sections 2.7, 5.8, 1.4 notes 10 and 11, 9.2, editor-ui §15 and sim-ui
§16: where the document is silent or does not fit what the repository has, what the code does,
and why. Entries under **Contract** concern declarations that other packages compile against.

## Import

### 1. The help folder holds a PDF that a page links to

- Says: nothing; 9.2 speaks of pages, images, the contents and the index.
- Found: `Quick Reference.htm` links to `EASy68KQuickRef.pdf` (184 KB). The import therefore
  copies every file of the help project except the build files (`help.chm`, `help.chw`, `help.hhp`,
  `ez68k.ali/.h/.txt/.xls`, the instructions text, the compiler log `Directives/Log1.log`,
  `Thumbs.db`) and the folder `EASy68K Icons` (program icons that no page uses). A reference to a
  file that is left out stops the import with an error, so this cannot regress silently.
- A browser's PDF viewer does not run inside a sandboxed frame; see entry 10 (the link opens in a new tab).

### 2. Counts of the case rewrites: 16 + 20 + 3

- Says: 39 references whose case differs, 16 in pages and 23 in `contents.hhc` and `index.hhk`.
- Found: the same, split 20 in `contents.hhc` and 3 in `index.hhk`. The four targets that do not
  exist are: `ac-archive.css` (from `GNU General Public License.htm`), `Reference/68ks2d.htm` (from
  `Reference/68ks1.htm`), a bare `top` (`file_operations.htm`) and `..\Helpv1_4\main.htm`
  (`index.hhk`). All four are in `app/public/help/manifest.json`. Besides these, the index has seven
  entries with a fragment (`Reference\68ks10.htm#*** CHK ***`) whose anchor does not exist in the
  page; the page exists, and the fragment is kept.

### 3. Encoding: UTF-8 for everything, declared in every page

- Says: "convert the encoding declaration and the bytes consistently".
- Does: pages, `contents.hhc` and `index.hhk` are decoded with the WHATWG `windows-1252` decoder
  and written as UTF-8 without a byte order mark; the 34 pages that declared `windows-1252` and
  the 123 that declared `iso-8859-1` now declare `charset=utf-8`, and the three that declared
  nothing (`excode.htm`, `GNU General Public License.htm`, `Quick Reference.htm`) get a `<meta>`
  line in their first bytes. Only two pages hold non-ASCII bytes (`credits.htm`: one `å`;
  `fileio.htm`: 133 no-break spaces). Line ends stay CR LF.

### 4. `app/public/help/manifest.json`, `README.txt`, `Reference/ATTRIBUTION.txt`, `Port/differences.htm`

- Says: nothing. These four files are added (generated by `tools/import-help.mjs`). The manifest
  is the list of imported files that the tests compare references against; the others are the
  attribution that O-5 asks for (inside `Reference/`, so removing the folder removes it with the
  pages), a note on what the import changes, and the page behind `app.help.differences`.

### 5. Help > Differences from EASy68K reads `docs/DIFFERENCES.md` at import time

- Says (1.5): "opens `docs/DIFFERENCES.md` rendered as a help page". `docs/DIFFERENCES.md` belongs to
  DOC1 and does not exist yet.
- Does: `tools/import-help.mjs` renders it with a small Markdown renderer of its own (headings,
  paragraphs, lists, code, quotes, tables, links, emphasis; no new dependency) into
  `help/Port/differences.htm`. While the file is missing the page says so. Whoever builds the
  release (DOC1, the gate) must run `npm run import:help` after `DIFFERENCES.md` is written and
  commit the result.

## Keyword table

### 6. `Credits.htm`, `SerialIo.htm` and the folders of the keyword table are spelled with the case of the files

- Says (editor-ui §15.3): pages as the original's alias file writes them (`reference/68ks8e.htm`,
  `directives/dc.htm`, `Directives/conditional.htm`, `Credits.htm`).
- Does: `core/help/keywords.ts` writes the letter case of the imported files (`Reference/...`,
  `Directives/...`, `credits.htm`), as the acceptance asks. A test compares keywords and pages with
  the table in editor-ui §15.3 ignoring case.

### 7. The word search of F1 is the original's, one quirk included

- editor-ui §15.3 gives the code. `helpKeywordAt` (core/help/context.ts) is a literal translation with
  the original's 1-based indexes. It keeps two behaviours that look like mistakes: the word always
  starts at the character before the caret (so `a,b` with the caret after the comma is the word
  `a,b`), and the last character of the text is never part of a word (`while (selectEnd <
Text.Length())`). Tests pin both.
- The port feeds it the caret's line, between two line ends (see the Contract entry below), so the
  second quirk shows only at the end of the document's last line. On the document's first line a
  caret at offset 0 gets no line end before it, so F1 does nothing there, as in the original (the
  first line is recognised by having no line before it in the editor's content while the editor is
  scrolled to the top).
- Keyword matching folds only A-Z (strcmpi) and the selection is trimmed of characters up to U+0020
  only (Delphi's Trim), not of NBSP.

## Panels and commands

### 8. F1 in Simulator mode opens the page of the focused panel

- Says: 1.3.4 and note 10: `Help > Sim68K Help` opens `SIMHELP/BasicOperation.htm`; "entry points
  that the original sends to the introduction by mistake open the page they were meant to open"
  (`SIM_BASIC`, `SIM_OPTIONS`, `MEMORY` in the memory window, `EDIT_OPTIONS`). `sim.help.context`
  has no row of its own.
- Does: `sim.help.context` (F1, `sim.help.help` is the menu item) opens `BasicOperation.htm`, or,
  while the focus is in the Memory, Stack, Hardware, Break Points or Log panel, `Memory.htm`,
  `Stack.htm`, `Hardware.htm`, `AdvBreakpoints.htm` or `SimOptions.htm`. The original's memory
  window opened the assembler's MEMORY directive page; note 10 says to open the page that was
  meant.

### 9. The panel attaches nothing to the page frame

- Says: 2.7: the pages are shown in a sandboxed frame "(no scripts)"; nothing about links or keys
  inside it.
- Found: the frame is a separate document, so the application's key dispatcher does not see its
  keys, and WebKit (Safari) refuses to run an event listener on the document of a frame that has no
  scripts: it logs "Blocked script execution ... the document's frame is sandboxed" for every event.
  Chromium runs such listeners. To behave the same in every browser the panel attaches nothing to the
  frame's document.
- Does: the frame is `sandbox="allow-same-origin allow-popups allow-popups-to-escape-sandbox"`.
  `allow-same-origin` lets the panel read the frame's address and title when it has loaded;
  `allow-popups` lets a link with `target="_blank"` open a new tab, which is how the original's links to
  the web already work. A link to another page navigates the frame by itself; the controller notices
  the load (`noteLoaded`) and records the page as a new history entry, so Back and Forward work.
  Consequences: Escape pressed while the page itself has the focus does not close the drawer (it does
  from the toolbar, the tree and the filter); Ctrl+C copies text from the page as the browser does; the
  browser's own Back button moves the frame back like any in-page navigation.

### 10. Four links get `target="_blank"`

- Says: "keep their content byte for byte except for what the entry tells you to rewrite".
- Found: three web addresses (`excode.htm`, `quickStart.htm`, the GPL page) and the link to the Quick
  Reference PDF have no `target`; the original's other web links (`main.htm`, `credits.htm`, ...) do. A
  PDF or another site cannot be shown in the sandboxed frame, so the import adds `target="_blank"` to
  these four anchors (and to any anchor of that kind that has none). The count is in
  `manifest.json` (`blankTargetsAdded: 4`); a test checks that every such link has a target.
- Desktop (DV2): a link with `target="_blank"` asks Electron for a new window. The main process must
  answer it with `setWindowOpenHandler`: send `http:` and `https:` addresses to the system's browser
  (`shell.openExternal`, allow-listed as `platform.openExternal` is) and deny everything else; a
  PDF is a file of the app and is shown by the `help` window or handed to the system.

## Contract

### C1. The editor's selection and caret are not in the contracts

- F1 in the editor needs the selected text and the text around the caret (editor-ui §15.3).
  `DocumentService` gives the document's text but not the selection or the caret, and the
  editor component's API is E2's. H1 reads the browser's own selection inside the region
  `data-e68-panel="editor"` (`features/help/editor-context.ts`): the selected text, or the line
  that holds the caret (`.cm-line` for CodeMirror). That works for CodeMirror 6 and for any
  contenteditable; it does not see a selection in a document that is not rendered.
- Wanted from W1/E2: a way to ask the active editor for `{ selected, text, caret }`, for example
  `DocumentService.selection(id)`. H1 would then replace the adapter's `readEditorWordContext`;
  nothing else changes. Filed as `docs/requests/H1-editor-selection.md`.

### C2. A feature cannot learn the port's version or its repository

- The About boxes show the version and link to the repository (1.4 note 11, O-14: not hard-coded).
  `buildInfo` is in `app/src/build-info.ts`, which a feature may not import (3.1), and `AppContext`
  has no field for it.
- H1 reads the version from the window title that the shell builds ("... - unofficial port
  <version>", `windowTitle` in `bootstrap.ts`; `portVersionFromTitle`) and falls back to the
  repository `gurmyd/easy68k-mac` (`DEFAULT_REPOSITORY` in `core/help/about.ts`), the address the
  task statement gives. Filed as `docs/requests/H1-build-info.md`.

### C3. There is no folder chooser in `FileDialogs`

- 5.8, desktop: "asks for a folder, copies them there and shows the open dialog in it". `FileDialogs`
  has `open` and `save` for files.
- H1 asks with `save` (title "Copy the Examples to (folder name)") and treats the name typed as the
  folder to create, then calls `open` with `startDir` set to it. A request for a real folder
  chooser (a `chooseFolder` member, DV2 and FS1) is `docs/requests/H1-folder-chooser.md`.

### C4. A modal dialog blocks the commands that would open help from it

- editor-ui §15.2: F1 and the Help button in the two option dialogs open `options.htm`.
  `CommandRegistry.run` does nothing while a modal dialog is open (3.12.2), and a feature may not
  import another feature's function.
- H1's `ed.help.help` and `sim.help.help` accept the page as their argument
  (`run('ed.help.help', 'options.htm')`), which works from a modeless dialog or from outside one. For
  a modal Options dialog E4 needs a way past the block; filed as `docs/requests/H1-help-from-dialogs.md`.
