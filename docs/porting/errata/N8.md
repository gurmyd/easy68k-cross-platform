## 5. The `.git` order: details the document leaves open

- "Below a folder named `.git`" is decided on the path below the folder being snapshot (`Vfs.snapshot`)
  or below the prepared root (`CachedSyncFiles`), with the segment compared in any letter case
  (`foldCase`). A program whose own folder lies inside a `.git` folder is therefore treated as any
  other. A FILE named `.git` (a work tree's or submodule's pointer) is not below a `.git` folder and
  keeps its place.
- `CachedSyncFiles` lists a tree in one place (`listTree`), used by `prepare`, `revalidate` and the
  refresh of a changed folder; the order applies to all three. A `.git` folder beyond the depth
  limit, or one that cannot be listed, is not named in the message area either; it stays
  unreachable as before. The files left out stay unreachable to the program, exactly as other files
  beyond the limits (they cannot be opened, created or removed).
- `Vfs.snapshot` names nothing (its `skipped` list reaches no message); its `.git` entries stay in
  `skipped` with their reasons, after the others.
- `belowGitFolder` and `isGitName` are exported from `fs/vfs.ts` for `cached.ts`; N3's
  `core/history/places.ts` has similar helpers for absolute paths, which `fs/` code of the snapshot
  did not take, so as not to depend on a file another package is still writing.

## 6. The reload offer: details the document leaves open

- "Receives an external change of its path": a Vfs change with origin `external` (another window
  of this browser or of the desktop app) of the document's file or of a folder above it. Changes
  this window makes (`local`) are not looked at: Save records the new time itself, Restore and Undo
  reload their documents (P3.3.8), and the window's own program writes are not "outside this
  window".
- "Regains the focus": the window's `focus` event, and `visibilitychange` to visible.
- A Save writes the file before it records the new time; a difference is therefore looked at twice,
  300 ms apart (`SETTLE_MS`), and offered only when it is still the same difference.
- A toast for a given modification time of a file is shown once; a later change is offered again.
- A file that is gone or cannot be reached is not offered (Save and Reload report it as before).
- The toast has the kit's default duration, and it appears in either mode. `Reload` runs
  `DocumentService.reload` only if the document is still open and not modified at that moment.
- Without `DocumentService.fileTime` (a stub service) the offer does nothing at all.
