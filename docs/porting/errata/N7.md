# Errata of N7 (Options > Port Additions...)

Where `docs/ARCHITECTURE-PLUS.md` P3.5 is silent, ambiguous or does not match the code, what
`app/src/features/additions/` does and why. Every text the document gives is used as written
(`features/additions/texts.ts`).

## 1. Figures of one thing are singular

P3.5 shows only plurals (`37 files`, `212 versions`, `4 items`), and P3.3.8's `Empty Trash` question
only `(12 items, 1.4 MB)`. One is written `1 file`, `1 version`, `1 item` (the question: `(1 item,
...)`); zero stays plural (`0 items, 0 bytes`). This follows `formatSize` of `core/history/size.ts`
(N3), which writes `1 byte`.

## 2. Sizes come from `formatSize`, so P3.5's `0.9 MB` and `0.3 MB` read `921.6 kB` and `307.2 kB`

P3.5's picture writes `212 versions, 0.9 MB` and `4 items, 0.3 MB`; P3.2.6 says sizes are written
with one decimal and the units bytes, kB, MB, GB, and the stage has one formatter for that,
`formatSize` (N3), which uses kB below 1 MB. The dialog uses it, so the picture's figures are
examples of the numbers, not of the unit chosen.

## 3. The site line without a quota, and without an estimate

P3.5 gives `This site uses 7.9 MB in this browser, about 1.8 GB free`. Not given, and chosen (as
P3.2.6 does for the Files panel's line): without `navigator.storage.estimate`, or when it rejects or
gives no `usage`, the line is left out; with a `usage` but no `quota`, the line ends after
`in this browser` (no free figure). "Free" is `quota - usage`, at least 0.

## 4. "The last two lines of the group" in the desktop app

P3.5: "Desktop app: the last two lines of the group are `Earlier versions and Trash are kept in the
app's own storage.`" That is one sentence. Read as: in the desktop app the two last texts of the
browser's group (`This site uses ...` and `Clearing this site's data ...`, which the picture draws
on three lines) are replaced by that one sentence. The estimate is not asked there.

## 5. `Empty Trash` with nothing in the Trash

Not given. Asking `Delete everything in the Trash for good? (0 items, 0 bytes)` would ask about
nothing; the button is not disabled either, because `{ group: 'storage' }` must be able to put the
focus on it. It shows P3.3.8's empty-state text instead (message box titled `Empty Trash`,
`information`, `OK`): `The Trash is empty. Files you delete in the Files panel stay here for up to
30 days; when the Trash is full, the oldest go first.` In the state `unavailable` the Trash reads as
empty (P4.4), so the same text is shown.

## 6. Titles and icons of the two questions

P3.5 and P3.3.8 give the texts and the buttons (`Yes`, `No`), not the title or icon. P3.3.4's rule
"titled with the command" is followed with the button's caption: `Empty Trash`, `Delete Earlier
Versions`; icon `confirmation`. The message box's default button is the kit's (`Yes`, the first);
P3.3.4's "No has the focus" is a rule of the question of P3.3.4 only, and `MessageBoxRequest` has no
member that chooses the default.

## 7. OK writes the switches the student changed

P3.5: "OK stores them". `app.plus.viewer` and `.history` are stamped per setting (P4.2), and a
write of a value that was not changed would stamp it as new and overwrite another window's later
change of it. OK therefore writes the switches whose box differs from what the dialog showed when it
opened (with `withPlus` of `core/plus/settings.ts`, so the other switch keeps its stored value); OK
without a change writes nothing. A changed switch is always written, also when it equals the default.

## 8. The focus without an argument

P3.5 gives the focus only for `{ group: 'storage' }` (`Empty Trash`). Without it the kit's rule
holds: the default button `OK` has the focus when the dialog opens.

## 9. Without `ctx.history`

`AppContext.history` is optional (P4.4). Without it both halves read `0 versions, 0 bytes` and
`0 items, 0 bytes`, and the two buttons are disabled. In the application the bootstrap always sets
it, so this is a test configuration only.

## 10. The Simulator's Options menu: after `Serial Ports...`, not after `Execution Speed...`

P3.5 places the item "after ... `Execution Speed...` (Simulator), below a separator". Since the
design was written, `Serial Ports...` (DV4) stands below its own separator after `Execution
Speed...`; N0 put `Port Additions...` at the end of the menu, below a separator after `Serial
Ports...`, which keeps "at the end of ... the Simulator's Options menu". `tests/e2e/sim/menus.spec.ts`
and `check-additions.mjs` assert that place.

## 11. The parity matrix needs no rows for the stage

`docs/requests/N0.md` section 4 asks to add the nine commands of P3.6 to `tests/parity/matrix.json`
if its test requires every command id there. It does not: `matrix.test.ts` requires exactly the
rows of the tables of `docs/ARCHITECTURE.md` 1.3 and 1.5 (a row not in the document fails as
`row is not in the document`), and the stage's commands are in neither table (N10 adds only a
pointer section 1.6). Nothing was added; `npx vitest run --config tests/parity/vitest.config.ts`
passes (15 of 15) with the changed `menus.spec.ts`, whose test titles are unchanged.
