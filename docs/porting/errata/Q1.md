## 1. A toolbar button's accessible name is its hint WITH the shortcut

- Says: 2.11, "every button has an accessible name equal to its hint".
- Code: `app/src/commands/menus.ts` `resolveToolbar` gives each button `label` = hint plus the
  platform's shortcut (`Open File (Ctrl+O)`), documented there as "the accessible name and
  tool-tip" (1.3.2: the toolbar appends the platform's shortcut to the original's hint); a
  disabled button may give its `disabledReason` instead.
- Audit: accepts the name when it equals that `label` or the `disabledReason`. Proposed text for
  2.11: "an accessible name equal to its tool-tip (the hint and its shortcut)".

## 2. Tool panels shown as tabs are tab panels, not regions

- Says: 2.11, "Panels are `region` landmarks named by their title. Tool tabs are a `tablist`."
- Code: a tool panel (Memory, Stack, Hardware, Break Points, Log) shown in the tool tab group has
  `role="tabpanel"`, named by its title; an element has one role.
- Audit: accepts `tabpanel` for a panel of the tool group, with the same name rule. Proposed text:
  "Panels are `region` landmarks named by their title, except those shown as tool tabs, which are
  the `tabpanel`s of a `tablist`."

## 3. "o hollow" instruction dot

- Says: 2.11, "breakpoints also differ in shape (`*` filled, `o` hollow)".
- Code: the instruction dot is filled with `--c-bp-off` at 35 % opacity inside its edge
  (`sim-main.css`), the breakpoint dot fully.
- Audit: checks that the breakpoint fill is opaque and the instruction fill at most half opaque.
  The shapes differ visibly in both themes (screenshots `*-walk-run-breakpoint.png`). Whether a
  screen reader is told about a breakpoint is a separate rule and fails (rc.md Q1-4).

## 4. The dialogs are more than the list of 2.7

- Says: 2.7 lists 19 dialog ids.
- Code: the features register 23 dialogs plus `message`: also `documents.drafts`, `files.name`,
  `print.range`, `sim.printerOutput`, `easybin.about` (each recorded in its owner's errata), and
  `sim.fileDialog` hands over to `file.open`.
- Audit: reads the list from the running application (`dialogComponents`) and fails if a
  registered dialog has no route in `tests/a11y/lib/scan.mjs`, so a dialog added later is not
  silently left out.
