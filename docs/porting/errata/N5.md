# Errata of N5 (the Files panel of the stage of additions)

Where `docs/ARCHITECTURE-PLUS.md` is silent, ambiguous or does not match the code, what N5 built and
why. No entry changes a contract.

## 1. Files N5 added that the entry of P5 does not list

- `app/src/features/files/texts.ts`: the package's texts (P5, introduction, asks for it; the entry
  of N5 does not name it).
- `app/src/features/files/MoveToDialog.tsx`: the dialog `files.moveTo`. P5 puts the dialog in
  `move.ts`; a dialog needs JSX, so the component is in its own `.tsx` file and the logic
  (`moveTargets`, `transferItems`, `refusedTarget`) stays in `move.ts`.
- `app/src/features/files/testing.ts`: test support of N5's unit tests (scripted dialogs, a fake
  DocumentService with the optional members of P4.4, a scripted HistoryService). Imported only by
  tests.
- `app/src/features/files/files-model.test.ts`: the seeded test of the last acceptance item.

## 2. `No has the focus` (P3.2.2, P3.3.4)

`MessageBoxRequest` (contracts/features.ts) has no way to name the default button, and the kit's
`MessageBox` gives the focus to the first button. The questions are `Yes`, `No` as before (FS1's
delete question did the same); `No` does not have the focus, so P3.3.4's "No has the focus" of the
cannot-keep question is not met. Filed as `docs/requests/N5-default-button.md` (an optional
`defaultButton` of `MessageBoxRequest`); when it is there, `cannotKeepConfirm` passes `'No'`.

## 3. `locations()` gains the linked root only for the Files panel

P5 says `locations` gains the linked root. `locations()` also feeds the Open and Save dialogs'
`Look in` list (FileDialog.tsx, dialogs.ts), which P3.2.5 does not change. So `locations(vfs, {
linked: true })` adds `/linked` as `Opened from this computer` (last), and `locations(vfs)` stays as
it was.

## 4. Texts P3.2 does not give, and the choice made

- Delete of 2 or 3 items: the names are joined `"a.X68" and "b.X68"` and `"a.X68", "b.X68" and the
  folder "demo" (14 files)`; with 4 or more the first three and `and N more` as P3.2.2 gives.
- A folder of one file: `(1 file)`.
- `Deleted 5 items. 1 of them was deleted for good.` for one (P3.2.2 gives only `2 of them were`).
- The title of the question that only removes linked files from the list: `Remove from List` (the
  command's name).
- The one-item move toast: `Moved "prog.X68" to demo.`; a copy: `Copied 3 items to demo.` /
  `Copied "prog.X68" to demo.` (P3.2.4 gives only `Moved 3 items to demo.`). The target is the
  folder's name, a store's root its label.
- `<label>` of `They are deleted from the folder "<label>" on this computer.`: the opened folder's
  own name (`Lab`, from the handle; FS2's label is `Folder: Lab`, see
  `docs/requests/N8-folder-place-text.md`); on the desktop app's disk, the name of the folder the
  item is in. When the selection mixes My Programs and the opened folder, the opened folder's
  sentence is used.
- The Replace question for a file inside a merged folder names it by its path below the target
  (`"demo/b.X68" already exists in My Programs/to.`), as Import names its conflicts.
- Sizes below 1 kB are whole numbers (`512 bytes`, `0 bytes`); every other unit has one decimal.

## 5. The not-enough-room message only for a large import

P3.2.6 gives the question for an import above 100 files or 10 MB, then "When the total size is
larger than the free space minus 32 MB: no question, the message". N5 reads the second as part of
the first ("no question" instead of the question): a small import is never refused by the
estimate, which is approximate (R7) and counts the application's own caches.

## 6. Move of a selection from two stores

P3.2.4: same store a move, different store a copy. A selection that holds items of two stores is
copied as a whole (each item stays where it was); a move of part of it would need two undo entries
for one command.

## 7. Items of the same name and other kind at the target

A file moved onto a folder of the same name (or a folder onto a file) is not merged or replaced:
the message (`Move`/`Copy`, `error`) `"demo" already exists.` (FS1's rename text) and that item is
skipped.

## 8. The linked files' root

- A file linked in this window (FS2's `LinkedBackend.link`) is added without a change event of the
  Vfs, so the tree lists the linked files again when a document of an unknown `/linked/...` path is
  open (the store's document list), and when the window regains the focus.
- Export of the root `Opened from this computer` exports its files as several items
  (`EASy68K export.zip`), not the internal folders.
- `Remove from List` removes `/linked/<id>` (the copy and its listings and S-records, FS2's
  `remove`), never the real file; it does not pass through `guard` (nothing of the student's is
  deleted) and has no Undo.

## 9. The strip

`Trash...` uses the icon `trash` as P3.3.3 says; FS1's `Delete` button used the same icon, so
`Delete` now shows `close` (its accessible name is unchanged). `Trash...` is disabled while
`app.files.trash` is not enabled (until N4's handler is there).

## 10. Rename and its Undo

Rename (`renameEntry`, unchanged) calls `moved(from, to)` once for the item (a rename never merges)
and `relocate(from, to)`, and pushes `Undo Rename`; it shows no toast (P3.2.4 gives a toast after a
move only). Undo Rename renames back through `renameEntry` (a change of letter case only included).
Undo of a move moves back file by file and never over anything.

## 11. What the storage line exposes for its check

The line carries `data-e68-storage-refreshes` (how many times it read the figures), so that
`check-files.mjs` measures "at most once per second" by the page's own clock.

## 12. The model test runs on `/browser` and `/disk`

`files-model.test.ts` mounts its second store at `/disk`, as N3's driver does. With a
`MemoryBackend` mounted at `/folder` (a FolderBackend without `rootHandle`), the checker reported
`(6) versions("/folder/t.X68") lists 1 of 0` after a plain save and `record` (seeds 1 to 3): the
store and the checker do not agree on the place of a `/folder` path without a root handle. A real
opened folder always has one (FS2's `FolderBackend.rootHandle`); the case is reported to N3 in the
result of N5, not worked around in N5's code.

Repair round 1 tried again with a root handle (`{ kind: 'directory', name: 'Lab' }` on the
MemoryBackend): the same report (`(6) versions("/folder/lab/t.X68") lists 1 of 0`, seeds 1, 3, 6).
The checker's `placeOf(path)` (`fs/history-model.ts`) has no root id for a `/folder` path; that is
N3's. The Files panel's own byte oracle (entry 13) does not depend on the store.

## 13. A selection that would lose a file is narrowed first (verify round 1)

P3.2.4 does not say what happens when the selection itself collides. N5 decided:

- An item inside another selected folder (after Ctrl+A) is dropped: the folder carries it
  (`outermostItems` in `bulk.ts`, used by Delete, Move and Copy). Delete counts it once.
- An item that is already in the target folder stays where it is; the others go. Only when every
  item is there is the target refused (as before).
- A second selected item whose name equals an earlier one's (letter case ignored) is not moved or
  copied: the message (`Move`/`Copy`, `error`, `OK`) `"p.X68" already exists.` (entry 7's text),
  and it stays where it is. Two same-named folders are not merged into one.
- A file that appears at the target after the command planned (and asked) is not written over: the
  same message, and it is skipped. Every overwrite still goes through `guard('replace')` only.
- Undo of a Copy always asks P3.3.4's question when guard cannot keep a copy (`Remove the copy
  anyway? This cannot be undone.`), whatever the history's state: it has no question of its own.

## 14. Rename and Undo Rename in a store that keeps letter case apart

A Linux disk (and the memory store of the tests) can hold `r.X68` beside `R.X68`. FS1's
`renameEntry` (not changed, P5) treats the exact match of the new spelling as the entry itself and
its case-only path then writes over the other file. The Files panel's Rename and Undo Rename call
`renameChecked` (`store.ts`), which refuses first with `"r.X68" already exists.`; Undo Rename names
it with `cannotMoveBackExists`. Found by the seeded model test's new byte oracle (seed 104).
