## 3. Risk R6 has no row marked **program**

P7 R6 says that taking `.git` files last "changes which files a program reaches when a folder is
beyond the limits", that P1.1 rule 1 names this exception, and that it gets no entry in
`docs/DIFFERENCES.md`. The task says a row marked **program** is a defect to report, not a row to

introduction of `docs/DIFFERENCES.md` and its list "What could change the results of a program"

says why, and an interface row says what the message area no longer names. The change itself is
described where R6 puts it, as the known limitation "A folder with a very large `.git`" in part 5 of

`README.md`, `CHANGELOG.md`, the guide and the introduction of `docs/DIFFERENCES.md` that say that the
additions change nothing a program does now add the same exception in a few words ("except which

For the architect: P1.1 rule 1 says "except", R6 says "no entry in DIFFERENCES.md", and the release
documents say "nothing a program can observe". Whether a case beyond the limits that a program can

## 5. `tools/check-guide-strings.mjs`: what it reads, and how the guide marks a text

- **The marks.** The guide's own convention is kept: **bold** for a caption (menu items, buttons,
  columns, titles; a menu path `**Menu > Item**` is checked part by part), one backtick for a text
  the application shows, two backticks for code type that is not checked (file names, chords). The
  rules stand in an HTML comment at the head of the section, and the tool says the same at its head.
- **Example names.** A text with a name in it (`Delete "prog.X68"?`) is matched against a template of
  the code. A template's `${...}` stands only for what the code puts there: the tool reads the
  expression and follows it through the code (any file of `app/src`, through its relative imports):
  the literals written in it (not the operands of a comparison), a local variable's or a constant's
  value, what a function of the code returns (`files(n)`, `formatSize(bytes)`, a `.join(', ')` list of
  such texts), a parameter's type when it is a set of strings (`side: BesideSide`), a number for
  `number`, `.length`, `.toFixed()` and arithmetic, and for any other parameter what the calls of the
  function pass there (in its own file and in the files that import it). What the code takes from
  outside (a parameter that no call of the code fills, a property of an object such as `item.name`)
  may only be one of the example names that the section's comment declares after `Example names:`
  (joined by `/` for a path), or a number. The same expression twice in one template is the same text.
  History: the first version let a wildcard stand for any text, so `Moves 3 items to demo.` (one
  changed letter) passed, and it counted the letters of a template with `/s/` instead of `/\s/`; the
  second let a wildcard stand for any text of the code (`Deleted Undo.`, `Moved Trash to demo.`,
  `"Undo" was changed outside this window.`, `Export all of Lab as demo.zip` and `Deleted 5 bytes.`
  passed: the second verdict on N10). The third, of the gate's fourth round, rejects all five; the
  unit test holds a small copy of each way the code builds a text and checks both what fits and
  what does not, and the command line fails on the guide with `Deleted Undo.`, a quote that fits no
  template. The example list gained the values the code takes from outside in the texts the guide
  quotes: `Files` (a panel's title), `EASy68K export.zip` (the name of an export, passed as a
  property), `no detail is known` (the history's detail, passed as a property) and `.git` (the label
  of an opened `.git` folder).
- **The files it reads.** The ten texts.ts files of the stage (`STAGE_TEXTS`: ui/dock, features/layout,
  files, history, viewer, additions, reload-offer, core/history, core/places, core/trash-restore),
  `commands/specs.ts`, and, beyond what P5 names, the menu tables `commands/tables/*-menu.ts`: the
  names of the menus (Window, View, File, Options) are there and not in specs.ts, and the guide quotes
  them in menu paths. The first version read every `app/src/**/texts.ts`, so texts of the faithful
  port (features/options, assemble, files-fsaccess) passed.
- **Not imported.** The texts.ts files import each other without file extensions, so Node 24 cannot
  import them; the tool reads their literals with a small tokenizer.
- **Not a browser check.** The name `tools/check-*.mjs` makes `tests/lint/ci-workflow.test.ts` take it
  for a browser check that must be in the plan step's table, so `npm run lint` fails until the gate
  applies `docs/requests/N10-check-guide.md` (an exclusion in that test and a step of the job `check`).
  The name is the one P5 gives.

## 7. The gate's fourth round: what the documents now say

The third round of the gate and the decisions of the fourth (22 November 2026) changed behaviour
that the documents described. Each statement was corrected where it stood:

- **Import into a `.git` folder (D-a, D-h).** Import is not refused in an opened folder that is
  itself a `.git` folder, and a picked, zipped or dropped folder named `.git` is treated as on main.
  The guide no longer says that the Files panel "never writes below" a `.git` folder: its Delete,
  Rename, New Folder, Move, Copy and Undo never do; Import, Save and a program write there as in the
  original. The guide and the N5 fragment quote the refusal as the code has it now (D-h):
  `The folder ".git" is the .git folder of a Git repository. Nothing was changed in it.` Part 5 of
  `docs/DIFFERENCES.md` lost its entry "An opened folder that is itself a `.git` folder refuses
  Import". The files engineer of this round edited the two `.git` rows of `docs/differences/N5.md`
  first (the text of D-h, Import unchanged); this package kept that edit and corrected the rest of
  the row ("nothing is written below a `.git` folder by a command of the panel" named Import too).
- **No as the default (D-b, D-g).** The guide says that every question whose Yes deletes or
  overwrites for good has No already chosen (Delete for Good, Empty Trash, Delete History and Trash,
  Delete Earlier Versions, and the Move, Copy and Trash restore replace questions when no copy can be
  kept); the fragments N4, N5 and N7 and the change log say the same.
- **The viewer's frame (D-c, D-j).** The N0 fragment said that a frame sent to the application's
  page shows a second copy of the application; it now says that the viewer shows its PDF again, and
  that in WebKit a frame sent to `about:blank` stays empty (the gap of D-j). Part 5 of
  `docs/DIFFERENCES.md` says the same, and the guide tells a student that a link inside a PDF brings
  the PDF back (in Safari a link to another site can leave the box empty). The desktop app's case is
  the new manual check E5 (the sentence of errata N6 14).
- **A document opened while a viewer is in front (O-1, errata N6 15).** The guide and the change log
  say that a document opened, created or chosen in the Window menu comes in front of the viewer.
  Neither the guide nor the manual list ever told the student to click the Editor's tab.
- **The fragments N0, N2 and N4.** N0's introduction is that of the others ("None changes what a
  68000 program can observe"; no row is marked program, entry 3). N2's Window menu row and N4's
  Earlier Versions row use the guide's corrected sentences (the split commands with one and with two
  panes; the file as it was stays in the list, usually as the newest `Saved` version).
- **V11.** It can be followed at any window width: in a wide window the Memory panel has a group of
  its own, so the tester first puts it into the group of Output with Move Panel To...; the expected
  announcements list all four forms of P3.1.8 that the steps can give, also
  `<panel> moved to the right edge of the window.`
