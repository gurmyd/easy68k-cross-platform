other, or do not match the code, what the documents of N10 do and why.

## 3. Risk R6 has no row marked **program**

P7 R6 says that taking `.git` files last "changes which files a program reaches when a folder is
beyond the limits", that P1.1 rule 1 names this exception, and that it gets no entry in
`docs/DIFFERENCES.md`. The task says a row marked **program** is a defect to report, not a row to
write. The first version of `docs/differences/N8.md` (written by N10) had such a row, and the
introduction of `docs/DIFFERENCES.md` and its list "What could change the results of a program"
named it; `README.md`, `CHANGELOG.md` and the guide said at the same time that the additions change
nothing a program does. The documents contradicted each other.

Repaired by following R6: `docs/differences/N8.md` has no row marked **program**; its introduction
says why, and an interface row says what the message area no longer names. The change itself is
described where R6 puts it, as the known limitation "A folder with a very large `.git`" in part 5 of
`docs/DIFFERENCES.md` and in the guide's "When something does not work". The sentences of
`README.md`, `CHANGELOG.md`, the guide and the introduction of `docs/DIFFERENCES.md` that say that the
additions change nothing a program does now add the same exception in a few words ("except which
files are left out first in a folder beyond the web version's limits"), as P1.1 rule 1 does.

For the architect: P1.1 rule 1 says "except", R6 says "no entry in DIFFERENCES.md", and the release
documents say "nothing a program can observe". Whether a case beyond the limits that a program can
detect (it lists its folder and finds a file missing that the faithful port would have loaded) should
be a row marked **program** after all is not N10's to decide. No reviewer of N8 found such a case
reported as observable; the documents now say the same thing everywhere.

## 5. `tools/check-guide-strings.mjs`: what it reads, and how the guide marks a text

- **The marks.** The guide's own convention is kept: **bold** for a caption (menu items, buttons,
  columns, titles; a menu path `**Menu > Item**` is checked part by part), one backtick for a text
  the application shows, two backticks for code type that is not checked (file names, chords). The
  rules stand in an HTML comment at the head of the section, and the tool says the same at its head.
- **Example names.** A text with a name in it (`Delete "prog.X68"?`) is matched against a template of
  the code. A template's `${...}` may stand only for a number (with one of the words the code's count
  and size helpers put after it), another text of the code, a list of such texts, or one of the
  example names that the section's comment declares after `Example names:` (joined by `/` for a
  path). The first version let a wildcard stand for any text, so `Moves 3 items to demo.` (one
  changed letter) passed; it also counted the letters of a template with `/s/` instead of `/\s/`.
- **The files it reads.** The ten texts.ts files of the stage (`STAGE_TEXTS`: ui/dock, features/layout,
  files, history, viewer, additions, reload-offer, core/history, core/places, core/trash-restore),
  `commands/specs.ts`, and, beyond what P5 names, the menu tables `commands/tables/*-menu.ts`: the
  names of the menus (Window, View, File, Options) are there and not in specs.ts, and the guide quotes
  them in menu paths. The first version read every `app/src/**/texts.ts`, so texts of the faithful
  port (features/options, assemble, files-fsaccess) passed.
- **Not imported.** The texts.ts files import each other without file extensions, so Node 24 cannot
  import them; the tool reads their literals with a small tokenizer.
- **Not a browser check.** The name `tools/check-*.mjs` makes `tests/lint/ci-workflow.test.ts` take it
  for a browser check that must be in the plan step's table, so `npm run lint` fails until the gate
  applies `docs/requests/N10-check-guide.md` (an exclusion in that test and a step of the job `check`).
  The name is the one P5 gives.
