### 5.3 Two findings

1. **Electron 45 draws the PDF with `plugins: false` too.** R5 says `plugins: true` "enables only
   its PDF viewer"; in Electron 45.4.1 on Windows the PDF viewer draws in a window with
   `plugins: false` as well. N0 made both changes the entry asks for (`plugins: true` in
   `APP_WEB_PREFERENCES`, `plugins: false` set explicitly in `CONTENT_WEB_PREFERENCES`) and the
   tests assert them; the setting is harmless, but it does not keep the PDF viewer out of content
   windows. Recorded in `docs/porting/errata/N0.md` (entry 5).
2. **Playwright's WebKit on Windows** reports `navigator.pdfViewerEnabled === true` and draws
   nothing. P3.4.2 shows the notice only when `pdfViewerEnabled` is false, so in such a build the
   viewer shows an empty frame with the line "If the PDF does not appear, use Export and open it
   with another program." under the strip. That line is the answer P3.4.2 already gives; N6's
   browser check must not expect the PDF to be drawn in WebKit (P3.4.2's last paragraph says so).

### 5.4 Three minutes for the owner

On a Mac with Safari, Chrome and Edge:

1. In a checkout of the branch `plus`: `npm ci`, then
   `EASY68K_BASE=/easy68k-cross-platform/ npm run build`, then serve `app/dist` under that path,
   for example `npx vite preview --base /easy68k-cross-platform/` from `app/` (N0 used a small

2. When the application is shown, open the developer console (Safari: Settings > Advanced > "Show
   features for web developers", then Develop > Show JavaScript Console; Chrome and Edge:
   Option+Cmd+J) and paste these lines. They build a one-page PDF in the page and show it as a
   `blob:` in an `iframe` in front of the application, as the viewer will; the frame inherits the
   page's policy. (N0 ran exactly these lines in the production build in headless Chromium, which
   drew the page, and in Playwright's WebKit on Windows, which showed an empty box, as in 5.1.)

   ```js
   (() => {
     const t = 'BT /F1 36 Tf 72 700 Td (EASy68K PDF test) Tj ET';
     const o = ['<< /Type /Catalog /Pages 2 0 R >>', '<< /Type /Pages /Kids [3 0 R] /Count 1 >>',
       '<< /Type /Page /Parent 2 0 R /MediaBox [0 0 612 792] /Contents 4 0 R /Resources << /Font << /F1 5 0 R >> >> >>',
       `<< /Length ${t.length} >>\nstream\n${t}\nendstream`, '<< /Type /Font /Subtype /Type1 /BaseFont /Helvetica >>'];
     let p = '%PDF-1.4\n';
     const x = [];
     o.forEach((b, i) => { x.push(p.length); p += `${i + 1} 0 obj\n${b}\nendobj\n`; });
     const s = p.length;
     p += `xref\n0 6\n0000000000 65535 f \n${x.map((n) => String(n).padStart(10, '0') + ' 00000 n \n').join('')}`;
     p += `trailer\n<< /Size 6 /Root 1 0 R >>\nstartxref\n${s}\n%%EOF\n`;
     const f = document.createElement('iframe');
     f.title = 'PDF: test.pdf';
     f.src = URL.createObjectURL(new Blob([p], { type: 'application/pdf' }));
     f.style.cssText = 'position:fixed;inset:40px;z-index:99999;width:80vw;height:80vh;background:#fff';
     document.body.append(f);
     console.log('pdfViewerEnabled', navigator.pdfViewerEnabled);
   })();
   ```

## 6. Notes for later packages

- **Commands without handlers.** The nine commands of P3.6 are in `COMMAND_IDS`, `specs.ts` and
  the menus, with no key, and disabled until their handler exists. `app/src/bootstrap.test.ts`
  lists them in `OWED_HANDLERS` with the package that owes each one (N1, N2, N4, N7): each package
  removes its own rows when its handler arrives (the test fails until then, so the list can only
  shrink).
- **Browser checks.** The five root scripts `check:dock`, `check:history`, `check:history-ui`,
  `check:viewer`, `check:status` and their rows in `ci.yml` exist; each CI step runs as soon as its
  file exists (`app/src/ui/dock/check-dock.mjs`, `app/src/fs/check-history.mjs`,
  `app/src/features/history/check-history-ui.mjs`, `app/src/features/viewer/check-viewer.mjs`,
  `app/src/ui/editor/check-status.mjs`). The plan outputs are named `dock`, `history`,
  `history_ui`, `viewer`, `status` (a shell variable cannot hold `-`). `check:dock`, `check:viewer`
  and `check:status` run in the group `interface`; `check:history` and `check:history-ui` in
  `integration`, the shortest group.
- **Stubs.** `fs/history-db.ts` returns a service whose `state()` is `'unavailable'`;
  `fs/history-memory.ts` is that service without an IndexedDB; `state/dock.ts` is a controller
  whose members do nothing (`locked()` true, `acceptsTransient()` false); `features/viewer`'s
  `createViewerService` wants nothing; `core/trash-restore/restore-flow.ts` answers every question
  with "cancel", "null", "false". The texts of `core/history/texts.ts` are final; those of
  `core/trash-restore/texts.ts` are written from P3.3.8 and P3.2.7 for N4 to use.
- **`browserHistoryDeps(ctx)`** fills `subtle` from `globalThis.crypto.subtle`, which is undefined
  outside a secure context (a page served over plain `http://` from another host than localhost).
  The contract types it as `SubtleCrypto`; N3's store must treat a missing `subtle` as
  `unavailable`.

## 7. Requests

1. **For NI (or whoever decides shared configuration in this stage): `fake-indexeddb` in
   `app/src/fs/history-memory.ts`.** P4.4 says N3's `history-memory.ts` imports the development
   dependency `fake-indexeddb`. It is not a test file, and the layer rule lets `fs/` import no npm
   package, so `npm run lint` will reject that import. P2.4 lists no allowance for it, so N0 did
   not add one. Suggested: in `eslint.config.js`, a `TEST_FILE_PACKAGES`-like entry
   `` [`${SRC}/fs/history-memory.ts`]: ['fake-indexeddb'] `` that applies to that one non-test file
   (it is imported only by tests and `state/testing.ts`, which no production code imports), with a
   passing and a failing case in `tests/lint/import-rules.test.ts`.
   **Done at the gate of the stage** (`TEST_ONLY_FILE_PACKAGES`; errata N0 entry 10).
