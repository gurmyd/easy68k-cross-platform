# Differences introduced by M2 (finding the arranging, ready-made layouts, version 1.1)

Deliberate differences between version 1.1 and version 1.0.0 (and the original), that this package
introduces (`docs/ARCHITECTURE-PLUS.md` P9.3, P9.4; `docs/porting/errata/M2.md`). None changes what a
68000 program can observe, a file the application writes, which panels are shown, or the original's
menus, commands and keys: the toolbar's new button comes after all of the original's buttons, and the
new menu entries after the original's items and the stage's. M3 wrote this file from P9 and the code
of M2; `tools/make-differences.mjs` merges it into `docs/DIFFERENCES.md`.

| Where | Original and 1.0.0 | Version 1.1 | Why |
|---|---|---|---|
| The toolbar of each mode | The original's buttons | The same buttons in the same places, then, after a separator, `Arrange Panels`: a toggle that is pressed while `Lock Layout` is unchecked (the tabs can be dragged). Its tool tip: `Arrange Panels: drag a panel by its tab, or right-click a tab for more (View > Lock Layout)` (`Window > Lock Layout` in the Editor). It runs `Lock Layout`; it is no new command | In 1.0.0 nothing on the screen said that the panels can be arranged (P9.1) |
| A tip, once | Not present | The first time the Simulator is shown, with no program running or waiting for input, a line above the status bar: `You can rearrange this window: double-click a panel's tab to make it float, drag tabs to dock them elsewhere, or pick a ready-made layout in the View menu.` (P9.8 point 3 (c)) with `Arrange Panels` (unlocks the layout) and `Got it`. It takes no keyboard focus and is announced politely. When a program starts it goes away unanswered and comes back when the program stops. After either button it never comes again in that browser profile, in any window | P9.3 |
| The Simulator's View menu | 1.0.0: `Move Panel To...`, `Lock Layout`, `Reset Layout` after the original's items | Also a submenu `Layouts` with `Classic` (the default arrangement, as `Reset Layout` gives it: floating panels dock), `Wide Output` (the Output panel the whole height of the right column, the tool panels a group below the Listing), `Output and Hardware Side by Side` (the Hardware panel in a column of its own beside the Output panel; the Output column gets the 648 pixels its picture at 100 % needs before the Hardware column gets more than its minimum, and the Hardware panel scrolls inside itself) and `Floating Tools` (every tool panel floats at its default size, side by side from the top right of the workspace, Hardware first, over no other floating window while there is room, never over the Hardware window's displays and switches; the docked panels keep the part of the workspace left of the windows, so that the Output picture stays in view: whole at 1920 by 1080 with Hardware and Memory shown, its left 400 pixels at 1366 by 768). None shows or hides a panel; each keeps the lock. The Editor and EASyBIN have none | P9.4, P9.8 points 1 and 5 |
| `Move Panel To...` | Three places: into a group, beside a panel, at an edge | A fourth place, `As a floating window` | P9.2 |
